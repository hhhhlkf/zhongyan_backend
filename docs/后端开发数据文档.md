# 后端开发数据文档

版本：v0.1  
依据：`后端重构计划.md`、当前仓库状态  
日期：2026-04-29

## 1. 当前基线

当前后端仍处于清洁重构早期阶段：

- 当前技术基线：`Spring Boot 4.0.6`、`Java 21`、`Maven Wrapper`。
- 目标技术基线：保持 `Java 21`、`Spring Boot 4.x`，后续随业务接入再升级小版本。
- 服务端口：`8088`。
- 服务上下文前缀：`/v2`。
- 当前未接入 JDBC/JPA 依赖，数据库尚未正式接入。
- 当前源码主要包含启动类和 `common` 基础能力，业务模块尚未完整落地。
- 后续不保留旧接口、旧返回结构、旧 Controller/Service/Dao 组织方式。

重构推进原则：

- 先建立领域边界和主业务链路，再接入真实基础设施。
- 先使用 mock 环境跑通，再替换为数据库、对象存储、事件总线、真实设备。
- 所有高风险动作必须通过 `TaskCommand` 和审批机制。
- 领域层不得依赖 Spring、JPA、Kafka、MinIO、JSch 等基础设施。

## 2. 环境安装顺序

### 2.1 基础开发环境

第一批只安装本地开发必需能力：

1. 安装 `JDK 21`。
2. 保留并使用 Maven Wrapper：`.\mvnw.cmd`。
3. 安装 Docker / Docker Compose。
4. 准备本地运行 profile：`local`、`test`。
5. 先验证当前工程可运行测试：

```powershell
.\mvnw.cmd test
```

说明：

- 当前仓库已迁移到 Java 21。
- 后续本地和 CI 环境都应使用 Java 21。
- 不建议一开始同时接入所有中间件，否则排障范围过大。

### 2.2 运行基线升级

建议在 Phase 1 工程骨架和领域模型稳定后升级：

1. 升级到 `Java 21`。
2. 升级到 `Spring Boot 4.x`。
3. 调整 Spring Security、Web MVC、测试依赖。
4. 重新执行：

```powershell
.\mvnw.cmd test
```

### 2.3 PostgreSQL / PostGIS / pgvector

数据库依赖应最先接入：

1. 安装 `PostgreSQL 16+`。
2. 安装 `PostGIS 3+`。
3. 安装 `pgvector 0.7+`。
4. 引入 Flyway 或 Liquibase。
5. 准备数据库初始化目录：

```text
deploy/
  init/
    postgres/
```

用途：

- Mission、Task、Command、Event、Asset 主数据。
- 空间几何和空间索引。
- Agent RAG 向量检索。
- outbox 事件表。

### 2.4 Redis

Redis 在数据库主链路之后接入：

1. 安装 `Redis 7+`。
2. 配置本地连接参数。
3. 用于运行态能力：
   - 分布式锁。
   - 设备在线状态。
   - 热点缓存。
   - 限流。

注意：

- Redis 不作为最终数据源。
- Redis 数据必须允许丢失后从主库或事件恢复。

### 2.5 Kafka

Kafka 应在 outbox 表和事件模型完成后接入：

1. 安装 `Kafka 3.x`。
2. 建立 topic。
3. 实现 producer / consumer。
4. 实现死信和回放机制。

建议 topic：

| Topic | Key | 用途 |
| --- | --- | --- |
| `task-events` | `taskId` | Task 生命周期事件 |
| `device-commands` | `deviceId` | 设备命令 |
| `asset-events` | `assetId` | 资产事件 |
| `uav-telemetry` | `uavId` | 无人机遥测 |
| `agent-events` | `sessionId` | Agent 事件 |
| `dead-letter-events` | 原始 key | 死信事件 |

### 2.6 MinIO

MinIO 在 Asset 模块开始落地时接入：

1. 安装 MinIO。
2. 创建本地 bucket。
3. 配置 access key 和 secret key。
4. 实现 `AssetStoragePort`。

用途：

- 图片。
- 视频。
- 模型结果。
- Attempt 原始日志。
- 报告。
- 附件。

注意：

- `src/main/resources/static/images` 只作为历史业务数据线索。
- 新业务数据不得继续以仓库静态目录作为主存储。

当前本地开发落地：

- `deploy/docker-compose.local.yml` 增加 `minio` 和 `minio-init` 服务。
- MinIO API 默认端口：`9000`。
- MinIO Console 默认端口：`9001`。
- 本地 bucket 默认名：`zhongyan-uav-assets`。
- 本地 access key 默认值：`zhongyan`。
- 本地 secret key 默认值：`zhongyan_minio_local`。
- `minio-init` 使用 `mc mb --ignore-existing` 幂等创建 bucket。
- `application-local.yml` 通过 `bms.asset.storage.*` 配置对象存储。
- `application-test.yml` 默认关闭真实 MinIO 适配器，避免单元测试依赖外部服务。

本地启动命令：

```powershell
docker compose -f deploy/docker-compose.local.yml up -d minio minio-init
```

已建立代码边界：

```text
src/main/java/com/zhongyan/uav/asset/
  port/
    AssetStoragePort.java
    AssetObject.java
    StoredObject.java
  infrastructure/minio/
    MinioAssetStorage.java
    MinioAssetStorageConfig.java
    MinioAssetStorageProperties.java
```

配置键：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `bms.asset.storage.enabled` | `true` in local, `false` in test | 是否启用真实 MinIO 适配器 |
| `bms.asset.storage.endpoint` | `http://localhost:9000` | MinIO API 地址 |
| `bms.asset.storage.access-key` | `zhongyan` | access key |
| `bms.asset.storage.secret-key` | `zhongyan_minio_local` | secret key |
| `bms.asset.storage.bucket` | `zhongyan-uav-assets` | 资产 bucket |
| `bms.asset.storage.region` | `us-east-1` | S3 region |
| `bms.asset.storage.presigned-expiry` | `PT15M` | 预签名读取 URL 默认有效期 |

### 2.7 GeoServer

GeoServer 在 PostGIS、Asset、MinIO 稳定后接入：

1. 安装 `GeoServer 2.25+`。
2. 配置 PostGIS 数据源。
3. 实现 `GeoServerPort`。
4. 实现图层发布任务。

注意：

- 图层发布属于高风险动作。
- 发布必须通过 `TaskCommand` 和审批机制。

本地环境落地约定：

- `deploy/docker-compose.local.yml` 使用 `docker.osgeo.org/geoserver:2.25.2`，满足 `GeoServer 2.25+` 要求。
- GeoServer 默认端口：`8080`，服务地址：`http://localhost:8080/geoserver`。
- 本地管理员默认账号：`admin`，默认密码：`geoserver`，可通过 `BMS_GEOSERVER_USERNAME` 和 `BMS_GEOSERVER_PASSWORD` 覆盖。
- 后端本地配置使用 `bms.geo.geoserver.*`，默认 workspace 为 `zhongyan`，datastore 为 `postgis`。
- 本阶段已完成容器、环境配置和端口边界；`GeoServerRestClient` 在发布时自动写入 PostGIS `asset_geometry`，并通过 GeoServer REST 创建 workspace、PostGIS datastore、feature type、style，再绑定默认 style。
- 本地 PostGIS 图层数据表由 `V6__asset_geometry_layer_publish.sql` 管理，几何列为 `geometry(Polygon, 4326)`。

### 2.8 Agent 依赖

Agent 相关依赖最后接入：

1. 引入 Spring AI。
2. 配置 OpenAI-compatible 模型服务。
3. 配置 embedding 服务。
4. 使用 pgvector 实现 RAG 检索。
5. 建立 Tool Gateway。

注意：

- Agent 不能直接执行启动、停止、删除、发布、覆盖等动作。
- Agent 写操作必须生成 `TaskCommand`。
- 所有工具调用必须写入审计记录。

### 2.9 可观测性

上线前接入：

1. OpenTelemetry。
2. Prometheus。
3. Grafana。
4. 指标、日志、链路追踪。
5. 压测和故障演练。

## 3. 代码编写顺序

### 3.1 Phase 1：工程骨架和领域模型

优先建立新包结构：

```text
src/main/java/com/zhongyan/uav/
  mission/
  task/
  configcenter/
  device/
  asset/
  geo/
  telemetry/
  event/
  realtime/
  agent/
```

优先编写纯领域模型：

1. `Mission`
2. `Task`
3. `TaskCommand`
4. `TaskEvent`
5. `TaskAttempt`
6. `Asset`
7. `TaskStateMachine`

同时建立 repository port：

- `MissionRepository`
- `TaskRepository`
- `TaskCommandRepository`
- `TaskEventRepository`
- `TaskAttemptRepository`
- `AssetRepository`

本阶段验证重点：

- Task 状态流转是否合法。
- 高风险命令是否进入待审批状态。
- 领域层是否不依赖 Spring/JPA/Kafka/MinIO/JSch。

### 3.2 API 空壳和 DTO

在领域模型之后建立新 API：

1. Mission API。
2. Task API。
3. Approval API。
4. Configuration API。
5. Asset API。
6. Telemetry API。
7. Realtime API。
8. Agent API。

要求：

- 只暴露新 `/v2` 路径。
- 不恢复旧路径。
- Controller 只调用 application service。
- Controller 不直接执行 SSH、文件扫描、设备控制、坐标计算。
- Request 使用 `*Request`。
- Response 使用 `*View`。
- 查询条件使用 `*Query`。

### 3.3 Application Service 和 Mock Repository

先用 mock 实现跑通主链路：

1. 创建 Mission。
2. 创建 Task。
3. 提交 Task。
4. 创建 TaskCommand。
5. 高风险命令进入审批。
6. 审批通过后进入调度。
7. 记录 TaskEvent。
8. 查询 Task、Command、Event、Asset。

优先应用服务：

- `MissionApplicationService`
- `MissionQueryService`
- `TaskApplicationService`
- `TaskCommandApplicationService`
- `TaskApprovalService`
- `TaskQueryService`

### 3.4 配置中心

配置中心在真实设备和任务执行前完成：

1. 建立 `DeviceConfig`。
2. 建立 `CameraConfigVersion`。
3. 建立 `ModelConfigVersion`。
4. 建立 `TransferConfigVersion`。
5. 建立 `ConfigValidation`。
6. 实现 `BootstrapConfigImporter`。

规则：

- 旧 `application.yml` 中设备、命令、路径、FOV 只作为一次性导入线索。
- 所有设备、相机、模型、传输配置必须先注册，再被 Task 引用。
- 每次配置变更创建新版本。
- 只有 `READY` 版本可以创建正式 Task。
- Task 创建时复制配置快照到 `configSnapshot`。

### 3.5 数据库和 Migration

配置中心和主链路稳定后接入数据库：

1. 取消 `DataSourceAutoConfiguration` 排除。
2. 添加 PostgreSQL、JPA、Flyway 或 Liquibase 依赖。
3. 新增 migration。
4. 实现 JPA repository adapter。

建议 migration：

```text
src/main/resources/db/migration/
  V1__core_mission_task_asset.sql
  V2__config_center.sql
  V3__telemetry_event_outbox.sql
  V4__agent.sql
```
